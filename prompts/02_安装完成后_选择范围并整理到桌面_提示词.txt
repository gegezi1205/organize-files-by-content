【阶段二：确认来源和职业身份画像，再把全部可处理内容整理到桌面】

请使用已经安装并能被当前 Agent 实际发现的 `$organize-files-by-content` 或当前 Agent 的等价调用方式。如果尚未安装、无法发现、版本不明或安全自测未通过，请立即停止，并提示我先执行 `01_只安装Skill_提示词.txt`。

先验证当前 Agent 确实能够在我的授权下读取、解析、移动和重命名本地文件，并能计算文件数量、大小和 SHA-256。如果当前环境只支持对话或上传文件，不能直接操作本地目录，请如实说明限制并停止，不得把建议方案说成已完成整理。

一、第一轮只确认整理边界和必要身份信息

现在先不要扫描或读取文件正文。除职业、职位、行业或工作场景、必要的多重身份，以及无法由 Agent 检出的自定义完整路径外，所有问题必须使用可点击控件或短编号选项；不得让我撰写说明、职责清单、排除规则或分类名称。每轮最多一个短屏，收到选择后再给下一轮。

1. 先按当前系统列出来源候选：桌面、下载、文档、Agent 能确认存在的常见工作目录、云盘同步目录、共享目录、外接存储，以及“其他完整路径”。让我逐项选择；只有选择“其他完整路径”时才让我提供路径。未选中的位置不得扫描。
2. 对已选来源逐个给出“整根纳入、先只列一级名称供选择、暂不纳入”选项。若我选择只列一级名称，这只授权读取该层名称；列出后让我点选需要纳入和排除的项，不让我自行书写排除规则。
3. 由 Agent 识别当前系统可能的真实桌面路径及 OneDrive、iCloud 或其他重定向，列成候选让我确认；只有无法识别时才让我提供完整路径。
4. 为每个来源提供个人工作、个人私密、团队共享、混合选项，以及读取、改名、移动、去重权限组合让我选择。混合范围默认只读，正式执行前按权限边界拆开；团队共享写入必须单独确认。
5. 只有职业、职位、行业或工作场景及必要的多重身份由我填写。当前、历史、兼职或副业、临时、非职业长期角色、大致时段和每个身份适用的来源，由 Agent 根据我填写的身份提供编号选项让我选择。可以使用宽泛职业表述，不要求单位全称或无关个人信息。
6. 再提供“本次范围与职业画像相关、部分相关、不相关、暂不确定”选项。选择不相关时可以跳过工作类型候选，但范围、权限、只读预览和执行确认仍不可跳过。

每一轮我未选择前只能等待。不得默认选择桌面和下载，不得扫描整台电脑，也不得用相邻目录替我补全范围。

二、生成工作类型候选，等待本人选择确认

仅当我选择本次范围与职业画像相关或部分相关时执行本节；选择不相关时记录 `profile_applies: false` 并跳过。

根据我填写的职业、职位、行业或工作场景，提出5—8项常见职责或工作类型候选。每项必须标注“这是常见假设，不代表你的实际工作”，并让我选择：

- 主责；
- 参与或协同；
- 仅接收、阅读或参考；
- 不适用；
- 已覆盖；
- 还有遗漏，请给下一组；
- 暂不确定，待只读盘点后再问。

工作类型确认后，再根据已选内容为以下判断元素分别给出短编号选项，不要求我自行撰写：

- 长期重复、阶段性还是一次性；
- 主要业务对象；
- 典型交付物或材料；
- 主要接收方或使用者；
- 常见周期或项目阶段；
- 通常先按项目、对象、稳定工作域、用途、人员、阶段还是时间查找；
- 正式包、敏感资料和不得改动的边界。

每轮控制在一个短屏内，并提供“全部确认、换一组/还有遗漏、暂不确定待盘点后再问”。如我选择“还有遗漏”，请根据尚未覆盖的身份维度继续给3—5项新候选，不要让我自行命名。展示“Agent 首轮候选、后续候选、本人选择”的记录，等我确认后再继续。未确认和“不适用”候选不得进入关键词、分类规则或隐性权重。

这是两级身份确认硬门槛：第一轮候选合计不超过8项，使用编号表格列出“关联身份、候选工作类型、提出依据、选择代码”，输出后立即停止。不得在同一轮继续给目录树、分类方案、命名规则或扫描计划。多重身份仍先控制总量；我选择“还有遗漏”时只给下一组并再次停止。只有我明确回复后才能继续：选择“已覆盖”可进入后续选项；选择“暂不确定，待只读盘点后再问”只允许在边界确认后做只读盘点，所有暂缓项解决或明确排除前不得设计正式目录、生成执行配置或移动文件。

三、回显精确边界和初步全景工作模型

1. 解析每个来源及桌面的真实完整路径，回显来源编号、授权层级、身份适用范围、允许操作、排除项、权限、同步和共享风险。
2. 把已确认判断元素串成初步模型：

   `身份 → 工作对象 → 常见工作类型 → 典型成果与接收方 → 周期或阶段 → 首要查找入口`

3. 标注每项的来源、置信度和仍缺少的证据。职业和职责是理解全貌的元素，不是一级目录。
4. 未经我确认的路径标记为未授权；路径不存在、不可访问或身份适用范围不清时先让我修正。
5. 等我确认边界后，且已确认画像或明确选择“暂不确定，待只读盘点后再问”，才进入只读盘点。

四、对每个确认来源分别做全量只读盘点

1. 只在确认范围内记录来源根、原路径、文件类型、大小、可读状态、可靠时间线索、SHA-256 和包上下文。不得越界读取父目录或相邻目录。
2. 桌面若同时是来源和目标，只统计一次，并保护现有合理分类。
3. 多个来源默认分别恢复分类逻辑、时间边界和包上下文；只有证据充分且我确认时才合并。
4. 抽样读取各主要聚类正文；正式执行前为授权范围内每个文件形成处理记录。结合原父目录、相邻文件、作者或创建者、发起方、接收方、业务对象、完整稿或局部填报、正文引用和实际留存用途判断。
5. 正在下载、同步中、仅云端占位、权限不足、损坏、加密、正在使用或共享影响不明的文件只记录为阻塞并保持原位。

五、用真实文件证据二次校正身份画像

1. 对照“已确认工作类型”和实际文件，列出：
   - 得到文件证据支持的工作类型；
   - 文件中反复出现但画像遗漏的工作类型；
   - 仅出现一次、可能是临时任务的内容；
   - 可能属于历史岗位、个人事务、他人材料或仅供参考的内容；
   - 职业候选与正文用途、原路径或共享规则冲突的内容。
2. 针对每类遗漏或冲突提供“当前职责、历史岗位、临时任务、个人事务、他人材料、仅供参考、暂不确定”等编号选项让我选择，不要求我撰写说明。不能因为职业常见就把文件归入该职业，也不能因为文件出现一次就把它升级为稳定职责。
3. 至少两类相互独立的判断元素互相印证后，才形成稳定规则；单一职业、单一关键词、单一文件或单一 mtime 只能生成候选。
4. 当前身份不能覆盖历史材料；不用 mtime 判断身份时期。旧材料被当前项目实际引用时，优先恢复当前项目或参考上下文。
5. 团队共享规则、正式包和操作权限高于个人职业画像；我只能确认有权决定的部分。

六、恢复习惯；完全混乱时保守兜底

1. 现有稳定目录、重复聚类、邻接关系、命名规律和查找入口是强证据，应优先沿用。
2. 不得把原本聚合的同类内容机械拆成大量桌面一级目录；改变核心逻辑前必须预览确认。
3. 如果某个来源几乎全是零散文件，明确写“未发现可复用的原分类模式”，不得假装理解。
4. 高度混乱时先冻结正式包、运行依赖、同步中和不可读内容；再结合已确认画像与正文用途形成少量候选聚类。普通单文件不自动一件一夹。展示2—3种最小桌面结构及取舍，让我选择并先做小批预演。

七、按真实用途设计桌面结构

1. 责任角色和存放维度分开判断。职业、主责、牵头、协同、作者或供稿人都不能直接决定一级目录。
2. 用途和上下文优先于组织名及“总结、规划、报告、会议”等普通词。
3. 根据实际用途区分独立项目、总结计划、会议材料、重要汇报或报送、参考资料、稳定类别、个人材料等，不从职业候选或其他人的目录复制专属分类。
4. 独立项目须有可识别身份、成组材料或阶段链条、较完整生命周期和持续查找价值。单份交付、总结、讲话页、会议供稿或一次性材料不足以成为一级项目。
5. 禁止无证据创建“综合工作、WORK、智能归档、杂项、已整理文件”等空泛层；一级入口必须可扫描。
6. 所有目标路径位于我确认的桌面内，不散铺桌面，也不额外套空泛总包；桌面已有合理入口时优先融入。

八、正式包、命名、日期、重复与版本

1. 会议包、报送包、正式提交包、证据包、导出包和运行目录保持正式名称、内部文件和相对结构完整。
2. 普通文件逐个审计名称。日期只能来自正文、封面、正式元数据或可靠原名，禁止用 mtime 冒充业务日期。
3. 文件名离开目录后仍应自解释，但不机械添加组织或职业前缀。
4. SHA-256 相同只证明内容相同。结合原路径、提交或证据角色、会议或报送关系、参考用途和正式包上下文，区分普通重复与情境副本。
5. 普通无意义重复只有在预览列明并经我确认后才清理；情境副本保留标记。无法确认新旧或用途时保持原位。

九、展示全量预览，等待我明确确认

1. 展示最终确认的全景工作模型、建议桌面分类树、调整前后一级目录数量、分类依据和至少5个真实改名示例。
2. 对每个授权来源分别给出覆盖数量，并生成全量处理预览，至少包括：来源根、原路径、拟定桌面新路径、内容摘要、关联身份、责任角色、实际用途、分类依据、命名决定、日期和版本依据、置信度、待选择项、SHA-256和情境副本状态。
3. 单独列出职业候选与文件证据冲突、历史或多重身份、共享权限、正式包保护、活动排除、同步风险、不可读文件和其他阻塞。
4. 多种解释并存时展示2—3个候选位置、证据和影响；文件保持原位。
5. 在我明确确认前，不得移动、重命名、覆盖或删除任何文件。

十、确认后执行并验收

内置 `organizer.py` 只处理单个配置根目录内的文件，不负责把多个电脑位置统一迁移到桌面。跨根任务必须由当前 Agent 按本次已确认的全量预览逐项执行；根目录外文件不得静默跳过，也不得把脚本存在说成跨根整理已完成。

1. 按确认预览执行；每个授权来源中的所有可处理文件最终进入桌面上的已确认分类路径。
2. 歧义文件逐项向我提问，不能用“其他”或“杂项”绕过选择。
3. 不可处理文件保持原位并列明阻塞；仍有未决项时必须说“尚未全部完成”。
4. 每次移动或改名后核对目标存在、文件大小和 SHA-256，保留“来源根 + 原路径 → 桌面新路径”索引。
5. 最终验收必须确认：画像中未确认或“不适用”项未进入路由；当前职业未覆盖历史、个人或共享材料；桌面一级入口可扫描；正式包结构完整；各来源没有仍可处理但未落到桌面的文件；索引、数量、大小和哈希一致。
6. 按来源报告盘点数、处理数和剩余数，以及改名、名称已合规、正式名称保护、重复与版本处理、待确认和阻塞数量。

本次只授权一次性整理明确选择的来源。不要创建投放箱、登录自启动、定时任务或后台监控；如以后需要自动化，必须另行确认、重建当前身份和路径配置，并至少完成一次真实投递测试。
