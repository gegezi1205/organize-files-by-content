中文显示名称：文件｜通用内容智能整理
英文技术名称：organize-files-by-content
标准调用名称：$organize-files-by-content
建议归类：优先归入当前 Agent 现有的“文件管理”类；如没有该类，则归入“效率工具”“办公自动化”或功能最接近的既有类别。不得只为本 Skill 新建一套分类。

详细中文简介：

面向不同行业、组织和个人的通用文件内容整理 Skill。它先确认用户明确授权的文件、文件夹和电脑位置，再请使用者填写职业、职位或多重身份，并根据这些必要信息提出少量常见职责或工作类型候选，由本人用编号或界面选项标记主责、参与、仅参考或不适用。候选未覆盖时只需选择“还有遗漏，请给下一组”，不要求本人另写职责清单。职业、职责、业务对象、典型成果、接收方、工作周期、协作关系、原目录和正文内容共同作为判断元素，用来逐步还原完整工作体系；任何单一职业或关键词都不会直接生成目录。

Skill 会先恢复使用者已有的分类思路、邻接关系和查找习惯。若文件长期零散混乱、无法提炼原有意图，会明确说明证据不足，提供少量候选结构和小批预演，不会假装理解或强行套用模板。只读盘点后，它会把实际文件与职业画像二次对照，区分当前职责、历史岗位、兼职或临时任务、个人事务、他人材料和仅供参考内容；共享资料的团队规则和权限高于当前操作者的个人画像。

分类判断以正文用途和完整上下文为主，结合原父目录、相邻材料、作者或创建者、发起方、接收方、业务对象、引用关系、完整稿或局部填报以及实际留存用途。主责、牵头、协同、配合、作者或供稿人只说明责任角色，不直接决定一级目录。独立项目须具有可识别事项身份、成组材料或阶段链条、较完整生命周期和持续查找价值等证据；单份总结、一次性交付或仅有负责人不足以自动建立一级项目。

Skill 能识别有证据的稳定类别、独立项目、总结计划、会议材料、重要汇报或报送、参考资料和个人材料等真实用途；保护会议包、报送包、正式提交包、证据包、导出包和运行依赖的正式名称、内部文件及相对结构。普通文件会逐个完成命名审计，日期仅采用正文、封面、正式元数据或可靠原名中的业务日期，绝不用文件修改时间冒充。

对于重复与版本，先以 SHA-256 识别相同内容，再结合原路径、用途和包上下文区分普通无意义重复与提交、证据、会议、报送、参考等情境副本；自动保留情境副本须有精确包边界或本人确认的路径，不能只凭目录中的普通词。存在多种解释、无法确认版本、不可读、加密、损坏、云端占位或同步中时，文件保持原位并列出候选解释或阻塞原因。获得用户确认后再移动、改名、覆盖或清理，并以原路径到新路径索引、数量、文件大小和哈希进行验收。安装、配置、启用和真实运行分别验证。

实际执行脚本会校验授权根目录、身份与权限确认、全量预览、暂缓项、情境副本保护和路径边界；配置中的 `..`、根目录外文件、符号链接逃逸或异常索引路径均拒绝处理。一次性整理授权不等于后台监控授权；真实投递验证通过且再次确认后，才能设置登录自启动。

Agent 适配边界：

本 Skill 不默认任何 Agent。安装时须查清当前 Agent 的实际 Skills 入口、发现和调用机制、中文元数据及分类方式；执行时须验证当前 Agent 确实具备用户授权的本地文件访问和操作能力。无法安装、发现或访问本地文件时必须如实报告，不能把文件上传、提示词已发送或脚本存在说成已安装或已整理。
