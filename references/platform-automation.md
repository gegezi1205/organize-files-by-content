# 跨平台自动投放箱

## 通用流程

1. 完成个人分类画像和配置。
2. 职业、身份、职责范围、共享权限、分类体系、一级入口或目标路径变化时，暂停旧路由，重新确认身份判断元素，重建配置并归档旧配置、旧路径映射和最后已知运行状态；不得继续沿用失效路由。
3. 用至少10个已知文件预演，覆盖职业候选与正文冲突、多重或历史身份、个人与共享边界、责任与用途冲突、同名组织不同身份、项目门槛、普通单文件、正式或会议包、情境副本和待确认。
4. 经使用者确认全量处理预览、清空待选择项并另行选择启用监控后，记录 `automation_context.enabled: true` 和 `monitor_confirmed_at`，才创建新配置默认投放箱 `00_待归档`。已有 schema 2 配置继续沿用原 `待智能整理`，不强制迁移。混合权限范围先拆分；团队共享范围另行确认写入授权。运行脚本会拒绝未完成这些确认的配置。
5. 如需自动解压压缩包或纠正文字图片方向，使用 schema 3，并在
   `media_processing` 中记录 `extract_archive`、`rotate_text_image` 与一次性
   `confirmed_at`。旧 schema 2 在未补充授权时只继续处理普通文件。
6. 运行 `watch_inbox.py --config 配置完整路径` 做前台测试。
7. 分别投放此前未处理过、去向明确的普通文件、文字图片和压缩包，确认监控收到、
   分类执行、必要的方向纠正或安全解压、目标落位和逐文件索引；成功后记录
   `real_delivery_test_passed_at`。
8. 只有完整测试成功且使用者再次确认登录自启动、记录 `autostart_confirmed_at` 后，才设置登录自启动；启用后再做一次真实投递回归测试。覆盖不同的既有自启动配置还需单独记录替换确认。

分别记录以下状态，不能合并表述：

- `已安装`：脚本或 Skill 存在；
- `已配置`：当前目录体系和路径已写入有效配置；
- `已启用`：前台监控或登录自启动已启动；
- `运行已验证`：至少一次真实投递完成接收、执行、落位和索引登记。

脚本存在或自启动文件生成，不等于监控已经运行成功。

## Windows

- 优先使用当前Python解释器运行 `watch_inbox.py`。
- 可由智能体在用户级“启动”目录创建启动脚本，或在任务计划程序中建立登录触发任务。
- 不要求管理员权限。
- 路径中可能含空格或中文，必须完整引用。

## macOS

- 优先创建用户级 LaunchAgent，或使用文件夹操作监控投放箱。
- 不监控整个桌面、下载目录或共享盘，只监控专用投放箱。
- 首次运行可能需要“文件与文件夹”权限。

## Linux

- 可使用用户级 systemd 服务，或登录脚本启动 `watch_inbox.py`。

## 限制

- 自动脚本只对个人配置中的高置信度规则执行正式归档，而且每个文件必须实际命中至少两类相互独立的证据来源；配置数字、重复关键词或单一标题词不能冒充证据闭环。目标层级沿用经确认的稳定入口；不创建无证据的“综合工作、WORK、智能归档、杂项”等空泛层，也不机械把全部类别拆到根目录。
- 无人值守监控不得自行重新推断职业、补充职责或创建新类别。只有本人确认的身份和工作类型可作为辅助语境；未确认或“不适用”的职业候选不参与路由。
- PDF或图片无法提取文字，或出现多个合理分类时，不得只凭扩展名猜测。交互运行应让使用者从 2—3 个候选项中选择；无人值守运行应发送桌面提醒、记录候选项并保持文件原位。
- ZIP、TAR、7Z、RAR 必须先按安全边界解压识别；缺少 7Z/RAR 安全解压器时明确
  记录原因。包内主件路线一致时整包归档并保留原包和相对结构，路线冲突时整包待选择。
  普通非压缩文件仍逐个处理，不得因为不是 ZIP 而机械进入待确认。
- JPEG、PNG、WebP 只在四向 OCR 有明确优势时纠正；正常图片、照片和低文字图片
  保持不动。Finder 元数据、Office 锁文件等运行项保持原位并从业务待确认统计中排除。
- 已位于稳定目录的文件优先沿用原路径、相邻材料和包上下文；主责或协同只说明责任，不自动决定一级目录。稳定类别下的事项不因“看起来像项目”自动提升；制度、讲话、参考和附件不得被单文件关键词抽走。Agent 可用重复邻接关系提出候选，但自动脚本只接受精确命中的已确认稳定路径；随机目录或随机邻居不能成为第二类证据。会议、报送、正式包和运行目录保持结构完整，自动脚本精确命中保护边界时只原位登记。
- 自动改名的日期最多到月份，并以正文或正式落款为准；制度、VIS、OA通知和正式包内名称受保护。
- 自动监控接收的每个普通文件都要重建并审计目标名称；只有当前名称已经与内容目标完全一致时才记录“名称已合规”，不能因分类路径正确而跳过命名。
- SHA-256相同仍须比较用途和包上下文；只有精确包边界或本人确认的情境路径才能自动保留情境副本。两个不同嵌套路径的用途关系未确认时保持原位待选择，不得用“会议、参考”等子串直接保留或删除。
- 云盘占位文件、正在下载文件、锁文件和未复制完成的文件暂不移动，但稳定后仍须由整理器登记为运行依赖或待处理状态。
- 主索引不得漏掉保持原位的待选择、不支持格式、系统元数据、包内副本和运行依赖；监控不得预先跳过隐藏或忽略项。可读取项记录大小和SHA-256，无法读取项明确登记失败、提醒使用者并阻断完成声明；同一实体重复运行只保留一条当前活动记录，原地修改后旧活动哈希立即失效。
- 如果智能体环境不能访问本地文件或创建后台任务，必须说明限制，不能声称安装成功。
